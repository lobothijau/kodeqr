# M1 — Redirect Service + Scan Pipeline (Week 1a)

**This is the milestone that must be correct.** The redirect route is the product's
contract with physical paper. Its failure modes (wrong destination, dead code, domain
blacklisted) are trust-fatal and mostly unrecoverable. Every task here is small on
purpose; review each diff line by line.

Invariants that hold across every task in this milestone:
- I1: The redirect request path performs **at most one Redis round-trip on hit** and
  never blocks on MySQL when cache is warm. No session, no CSRF, no Inertia.
- I2: The redirect path **never throws to the scanner.** Any internal failure degrades
  to a 302 (if destination known) or the branded unavailable page — never a 500.
- I3: Nothing in the scan-recording path can delay the redirect response. Record =
  fire-and-forget into Redis; process later.
- I4: Raw IPs exist only in-request. Only `ip_hash` is ever queued or stored.
- I5: A destination is never redirected to unless it passed Safe Browsing at its most
  recent create/edit.

## M1-T1 — Redirect route skeleton + status pages — size M
**Scope:** `routes/redirect.php` loaded with minimal middleware group `redirect`
(throttle + nothing else; explicitly NOT `web`). `GET /x/{slug}` →
`RedirectController::__invoke`. Resolution: `Cache::get("qr:$slug")` → on miss, DB
lookup, then `Cache::put` TTL 6h storing `{dest_url, status, plan, scan_cap,
scan_count_key}`. Response by status: `active` → 302 with
`Cache-Control: no-store` (a cached 302 in a phone browser survives destination edits
— this header is load-bearing); `paused`/`over_quota` → 410 Blade page (kodeqr-branded,
Bahasa, "Kode ini sedang tidak aktif"); `blocked` → 410 abuse page (no destination
shown); `grace` → interstitial (M1-T6); unknown slug → 404 branded page. All status
pages static Blade, no DB, cacheable.
**Not building:** scan recording (T3), interstitial logic (T6), bot handling (T4).
**Implementation notes:** slug route constraint `[1-9A-HJ-NP-Za-km-z]{6}`; reject
others at the router (no DB hit for garbage paths — this route will be fuzzed by
scanners). Cache key invalidation lives in a `QrCodeObserver` on saved/deleted:
`Cache::forget("qr:$slug")`.
**Acceptance:** (a) warm hit issues 0 SQL queries (assert with query log in test);
(b) editing destination then re-requesting within 1s returns the NEW url; (c) each
non-active status returns its page with 410/404 and no `Location` header; (d) 100
requests to invalid slugs execute 0 SQL queries.
**Review focus:** the middleware group. If `web` middleware leaks onto this route,
every scan pays session + cookie cost and I1 is broken silently.

## M1-T2 — Slug generation + QrCode model rules — size S
**Scope:** `SlugGenerator::make()` — 6 chars from alphabet
`23456789ABCDEFGHJKMNPQRSTUVWXYZabcdefghjkmnpqrstuvwxyz` (57 chars ≈ 34 bits),
retry-on-collision loop (max 5, then 7-char fallback). `destination` json shape per
type: url `{url}`; whatsapp `{phone, text}` → rendered to
`https://wa.me/{phone}?text={urlencode(text)}` at save-time into a derived
`dest_url` attribute stored inside destination json (redirect path never
string-builds). Phone normalization: strip non-digits, `0…` → `62…`, reject < 9 digits.
**Not building:** file/vcard/linkpage types (M3/M4 extend the same shape).
**Acceptance:** 10k generated slugs, zero collisions in test; `08123456789` →
`wa.me/628123456789`; `+62 812-3456` normalizes; text with `&` and emoji round-trips
scanning correctly.
**Review focus:** save-time rendering — if dest_url is built per-request, I1 dies later.

## M1-T3 — Scan capture buffer (redirect side) — size M
**Scope:** inside `RedirectController` after response is prepared: build payload
`{slug, qr_id, t: now()->timestamp, ip_hash, ua: substr(ua,0,255), ref}` and
`Redis::rpush('scans:buffer', json_encode($payload))` wrapped in try/catch that logs
and continues (I2/I3). Scan-cap enforcement: `Redis::incr("qr:sc:$qr_id")` (seeded
from DB scan_count on cache fill); if plan has cap and counter > cap → serve
over_quota page instead of 302 AND dispatch a queued job to flip DB status to
`over_quota` (so dashboards agree). ip_hash per TASKS.md formula, computed from
`CF-Connecting-IP` (Cloudflare) with `REMOTE_ADDR` fallback.
**Not building:** the consumer (T4); uniqueness (T4).
**Acceptance:** (a) Redis down (stop it in test) → scanner still gets 302, error
logged once; (b) 501st scan on a free code serves over_quota page and DB status flips
within one queue cycle; (c) payload in buffer contains no raw IP (regex assert);
(d) buffer write adds < 2ms p95 to route (benchmark assertion, generous bound).
**Review focus:** the try/catch actually covers BOTH rpush and incr; header
precedence (CF-Connecting-IP spoofable only if orange-cloud bypassed — note, accept).

## M1-T4 — Scan processor job + bot filter + GeoLite2 — size L
**Scope:** `ProcessScanBuffer` scheduled every minute: `LPOP scans:buffer` in chunks
of 500 (loop until empty or 10k), for each: parse UA (`whichbrowser/parser` or
matomo device-detector — pick one, note why), bot check, geo lookup, uniqueness
check, then **single bulk insert per chunk** into scan_events. Bot list (UA
substring, case-insensitive): `whatsapp, facebookexternalhit, telegrambot, twitterbot,
slackbot, discordbot, linkedinbot, googlebot, bingbot, applebot, petalbot, headless,
curl, wget, python-requests, go-http-client, okhttp` → insert with `is_bot=true`
(kept for debugging, excluded from all dashboards & aggregates). Uniqueness:
`Redis SET uq:{qr_id}:{ip_hash} 1 NX EX 86400` → `is_unique = (bool)$result`. Geo:
`geoip2/geoip2` against local mmdb `storage/app/geoip/GeoLite2-City.mmdb`; lookup
failure → nulls, never a dropped event. Separate artisan command
`geoip:update` (download via MAXMIND_LICENSE_KEY, atomic rename) scheduled weekly.
Also increments `qr_codes.scan_count` and `last_scanned_at` via one
`UPDATE ... CASE` per chunk (not per event).
**Not building:** aggregates rollup (M5-T1), dashboards.
**Implementation notes:** if a chunk's bulk insert throws (e.g. deadlock), RPUSH the
chunk's raw payloads back and rethrow → retried next minute. Idempotency: payloads
carry a `uuid` set in T3; insert uses `insertOrIgnore` on a unique index over
(`qr_code_id`,`uuid`)… simpler: add `event_uuid` char(26) unique to scan_events in
this task's migration. **Replaying the same chunk twice must produce one row.**
**Acceptance:** (a) push 1,200 fake payloads → exactly 1,200 rows, 3 bulk inserts,
scan_count correct; (b) re-run processor against a re-pushed duplicate chunk → row
count unchanged; (c) WhatsApp-preview UA → is_bot true and absent from a dashboard
query; (d) same ip same day → second event is_unique=false; next day (advance clock)
→ true again; (e) kill MySQL mid-run → buffer retains unprocessed payloads, no loss.
**Review focus:** the requeue-on-failure path and the unique index. This is the most
intricate task in the project; expect the first diff to get idempotency subtly wrong.

## M1-T5 — Safe Browsing gate on create/edit — size M
**Scope:** `SafeBrowsingClient::check(string $url): SafeBrowsingResult` — POST
`threatMatches:find` with threatTypes `MALWARE, SOCIAL_ENGINEERING,
UNWANTED_SOFTWARE, POTENTIALLY_HARMFUL_APPLICATION`, platform `ANY_PLATFORM`.
Wired as a form-request `after` hook on QR create AND on every destination edit
(I5). Match → 422 `destination.url: "URL ini terdeteksi berbahaya dan tidak dapat
digunakan."` + insert into new `abuse_flags` table (`qr_code_id` nullable, `url`,
`source` enum(`safe_browsing`,`report`,`admin`), `threat_type`, timestamps). API
error/timeout (2s): **fail-open on create but log + queue a recheck job in 10 min**
(fail-closed would let a Google outage block all signups; the recheck closes the gap).
Recheck hit → status `blocked` + cache forget.
**Not building:** nightly full re-scan (M4-T6), admin UI.
**Acceptance:** (a) Google's test URL `http://malware.testing.google.test/testing/malware/`
rejected with the Bahasa message; (b) clean URL passes adding < 400ms p95 to save;
(c) API timeout → code saves, recheck job on queue; (d) recheck flags → status
blocked, next scan of that slug gets abuse page not 302 (this closes I5 end-to-end).
**Review focus:** edit path coverage — the classic hole is checking create only,
letting an attacker create clean then edit dirty. Assert the edit test exists.

## M1-T6 — Free-tier interstitial + grace interstitial — size M
**Scope:** for `active` codes whose owner plan has `interstitial=true`: serve Blade
splash instead of 302 — kodeqr logo, "Anda akan diarahkan ke **{host}**" (show
destination host — anti-phishing transparency), 2.5s `meta refresh` + "Lanjutkan"
button + "Buat QR gratis → kodeqr.com". `grace` status: same layout, banner "Kode ini
akan berhenti aktif dalam {days} hari" (days from subscription grace_ends_at passed
through cache payload), still redirects. Splash pages emit the scan payload
identically to 302s (the splash IS a scan).
**Not building:** paid-lapse state machine (M3-T3 flips statuses; this task only
renders them), A/B, design polish (cut-list item 8 covers plain fallback).
**Acceptance:** (a) free-plan code scan → splash showing correct destination host,
auto-redirects ≤ 3s on a real phone; (b) paid-plan code → direct 302, no splash;
(c) splash records exactly one scan event (not two — watch the meta-refresh
double-fire); (d) upgrade the owner in tinker → cache invalidated → next scan is a
direct 302 with no deploy.
**Review focus:** double-count on meta refresh: payload push must be server-side on
the splash render, and the /x route must not re-push when the refresh target is the
destination (it is — refresh goes straight to dest_url, verify).

## M1-T7 — Report-abuse endpoint + kill switch — size S
**Scope:** public `GET/POST /laporkan` (rate-limit 5/min/IP, honeypot field): slug or
full /x URL + reason enum(`phishing`,`malware`,`penipuan`,`lainnya`) + optional email
→ `abuse_flags` row source `report` + notification mail to admin. Artisan
`qr:block {slug} {--unblock}` flips status + forgets cache — the 60-second kill
switch for the pre-admin-UI era.
**Acceptance:** report on nonexistent slug still 200 (no enumeration oracle); block
command → next scan sees abuse page < 5s later; unblock restores 302.
**Review focus:** enumeration — response identical whether slug exists or not.

## M1-T8 — Redirect observability — size S
**Scope:** scheduled `redirect:health` every minute: self-request a canary slug
(seeded, owner=system) via Cloudflare URL, assert 302 + latency; two consecutive
failures → email + log critical. Dashboard-less metrics: daily scheduled log line
`scans_buffered / processed / bot_pct / p95_redirect_ms` from Redis counters.
**Acceptance:** stop the app locally → two cycles → alert email observed. Canary
scans excluded from all analytics (owner=system filter).
**Review focus:** canary goes through Cloudflare + full stack, not localhost loopback.

## GATE G1 — ADVERSARIAL. Real deployed env, real phone camera. Do not skip lines.

Happy path first:
- [ ] Print a code (paper, not screen). Scan with iPhone camera, Android camera, and
      in-app WhatsApp scanner. All land < 1.5s perceived on cellular.
- [ ] Edit destination in dashboard; re-scan same paper < 10s later → new destination.
- [ ] Free-tier splash shows correct host; paid code skips splash.

Now try to break it — each line is "do the bad thing, confirm the safe outcome":
- [ ] **Kill Redis** (Cloud dashboard, pause Valkey). Scan paper code → still redirects
      (DB fallback path) or serves branded unavailable — anything but 500/blank.
      Restore, confirm buffered/lost window is only the outage span.
- [ ] **Kill the queue worker** for 10 min under scans → redirects unaffected, buffer
      grows, restart drains it, event count matches scans performed (count by hand).
- [ ] **Replay attack on the processor:** copy 200 payloads, push them twice → row
      count increases by exactly 200.
- [ ] **Phishing lifecycle:** create code → clean URL passes → edit to Google's test
      malware URL → rejected with Bahasa error. Force-write a dirty URL via tinker →
      recheck job flags → scan shows abuse page, not redirect.
- [ ] **Scan-cap race:** hammer a free code from 490→520 scans with `ab -n 30 -c 10`
      → counter never lets it materially past 500 (±concurrency slack ≤ 5), page
      flips to over_quota, dashboard status agrees.
- [ ] **Cache poisoning check:** edit destination, then scan from a phone that scanned
      pre-edit (browser had the old 302 cached?) → lands on NEW destination
      (Cache-Control: no-store did its job).
- [ ] **Slug fuzz:** `for i in $(seq 200); do curl -s kodeqr.com/x/$RANDOM$RANDOM; done`
      → all branded 404s, SQL query log shows zero queries, no error-log spam.
- [ ] **Link-preview pollution:** paste a /x link into a WhatsApp chat (don't open) →
      preview fetch appears as is_bot=true, dashboard scan count unchanged.
- [ ] **Enumeration:** /laporkan responses byte-identical for real vs fake slug.
- [ ] **Canary alarm:** block the canary slug → alert email within 3 minutes. Unblock.
- [ ] Deliberately deploy a broken revision to preview env → confirm production
      redirects were never in the deploy path's blast radius (Cloud atomic deploys).

G1 passes only when every box is checked in one sitting on production infra.
