# M5 — Launch Surface (Week 4)

Performance debts come due, plus the public faces: API, SEO tools, invoices.

---

## M5-T1 — Aggregates rollup + StatsRepository swap — size L
**Scope:** nightly `stats:rollup {--date=}`: per code per day → upsert
scan_daily_aggregates + scan_dim_aggregates (city/device/os/hour, top-20 keys per
dim, excluding bots). Swap `StatsRepository` impl: ranges ending before today read
aggregates; today reads raw; stitched seamlessly. Backfill command for existing
events. **Idempotent: re-running a date upserts, never doubles.**
**Acceptance:** rollup for a seeded day, run 3× → aggregate rows identical;
dashboard numbers before/after swap byte-identical for a 30d range (golden test);
90d range on 100k-event code < 200ms (was seconds).
**Review focus:** the today/history stitch boundary (off-by-one day in WIB).

## M5-T2 — Public API v1 + docs — size L
**Scope:** Sanctum tokens (settings page, Plus+): `POST /api/v1/qr` (create),
`GET /api/v1/qr`, `GET /api/v1/qr/{id}`, `PATCH /api/v1/qr/{id}` (destination/
status), `GET /api/v1/qr/{id}/stats?range=`. Quota per PlanConfig api_quota
(monthly, Redis counter, `X-RateLimit-*` headers, 429 over). Static docs page
(Blade + code samples curl/js/php).
**Acceptance:** full CRUD via curl only; quota 3000+1th call → 429 with reset
header; token of lapsed-to-free user → 403 on create (plan gate applies).
**Review focus:** API bypassing web-side gates — must call the same Entitlements
service (grep for duplicated limit logic; zero).

## M5-T3 — Retention pruning — size M
**Scope:** nightly `scans:prune`: delete scan_events (and link_clicks) older than
owner plan retention_days (free 7, Reg/Plus 365, Business never) in 5k-row
batches with sleep, AFTER that date's rollup is confirmed present (aggregates
survive forever — dashboards degrade gracefully to aggregate-only for old ranges).
**Acceptance:** free user's day-8 raw events gone, day-8 aggregate chart still
renders; prune of 200k rows doesn't lock writes (run while hammering redirects
in a load loop — buffer processes uninterrupted).
**Review focus:** the rollup-exists guard — pruning an un-rolled day destroys
data irrecoverably. Assert the guard has a test.

## M5-T4 — /scan tool + SEO generator pages — size M
**Scope:** `/scan`: browser QR scanner (jsQR + getUserMedia, camera + image
upload, zero upload to server) with "buat QR-mu sendiri" CTA. Static generator
pages `/buat/{link,whatsapp,wifi}`: free STATIC QR client-side render + download
(unlimited, no account), each with 300-word Bahasa SEO copy + CTA to dynamic.
Sitemap.xml, meta/OG pass on all public pages.
**Not building:** more page types, blog.
**Acceptance:** /scan reads a paper QR via laptop webcam; wifi static QR joins a
real network from Android camera; Lighthouse SEO ≥ 95 on the three pages;
static generation makes zero API calls (network tab clean).
**Review focus:** camera permission fallback (no camera → upload path, no
white screen).

## M5-T5 — Landing page — size M
**Scope:** kodeqr.com root: hero with the disambiguation line ("Bukan QRIS — QR
marketing yang bisa diedit & dilacak"), live demo widget (type URL → styled QR
appears), 3 use-case sections (F&B/menu, kreator/linkpage, event/bulk), pricing
strip, footer (laporkan, kebijakan privasi, kontak WA). Uses frontend-design
skill conventions.
**Acceptance:** LCP < 2s cellular mid-range Android; the two-friend test from G3
repeated on landing copy; demo widget QR actually scans off-screen.
**Review focus:** hero copy triage — a QRIS-seeker should self-identify as wrong
audience within 5 seconds.

## M5-T6 — Invoice PDFs (Business) + billing history — size S
**Scope:** billing history page all tiers; Business: PDF invoice per paid order
(dompdf template: kodeqr entity details, order id, plan, period, amount, "Lunas"
stamp) downloadable + auto-emailed.
**Acceptance:** PDF opens in WhatsApp preview (how it'll actually be shared with
finance teams); totals match order integer amounts.
**Review focus:** none deep — template task; check rupiah formatting
(Rp 1.490.000, dots not commas).
