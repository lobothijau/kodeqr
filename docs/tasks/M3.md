# M3 — Money + Menu (Week 2)

Payments ride the boilerplate's billing tables; these tasks wire kodeqr plans,
Midtrans specifics, and the never-cut grace behavior. Then the F&B wedge (file QR)
and Bahasa.

---

## M3-T1 — Midtrans checkout (prepaid periods) — size L
**Scope:** Snap-based checkout for plan purchases: `subscription_orders` table
(`id` ulid, `user_id`, `plan`, `period` enum(`monthly`,`annual`), `gross_amount`
int, `midtrans_order_id` varchar unique, `status`
enum(`pending`,`paid`,`failed`,`expired`), `paid_at`, timestamps). Flow: pricing
page → create order (`order_id = "KQR-{ulid}"`) → Snap token (enabled payments:
`qris, gopay, shopeepay, bank_transfer, credit_card`) → popup. **No auto-renew** —
prepaid periods per TASKS.md; annual = monthly×10.
**Not building:** webhook (T2), invoices (M5-T6), proration/refunds (manual policy).
**Acceptance:** sandbox QRIS simulator payment → order `paid`; abandoning popup
leaves order `pending` and plan unchanged; amounts are integers (no float rupiah
anywhere — larastan-assert int casts).
**Review focus:** order_id uniqueness + amount computed server-side only (client
sends plan+period identifiers, never a price).

## M3-T2 — Midtrans webhook + entitlement activation — size M
**Scope:** `POST /webhooks/midtrans` (CSRF-exempt, in `api` group): verify
`signature_key == sha512(order_id + status_code + gross_amount + ServerKey)`;
map `settlement|capture(accept)` → paid, `deny|cancel|expire` → that status.
On paid: extend/create the boilerplate subscription row —
`ends_at = max(now, current_ends_at) + period` (stacking top-ups extend, never
overwrite), plan upgraded immediately if higher tier. Idempotent: replayed
notification for a paid order is a 200 no-op.
**Acceptance:** (a) valid sandbox notification activates plan; (b) tampered
gross_amount → 403, order untouched; (c) same notification POSTed 3× → one
activation, ends_at moved once; (d) buying monthly twice → ends_at = +2 months.
**Review focus:** the signature formula operand order and idempotency guard —
the two classic webhook bugs.

## M3-T3 — Lapse state machine: grace, not guillotine — size M
**Scope:** daily `subscriptions:reconcile`: for subs where `ends_at < now` →
mark grace (`grace_ends_at = ends_at + 14d`), flip ALL owner's active codes to
`grace` (+cache forget each). Where `grace_ends_at < now` → codes above the FREE
plan's limits: 3 newest stay `active`-as-free (splash on), rest → `paused`; email
at lapse, at grace-day-10, at pause. Renewal during grace → everything back to
`active` instantly (webhook path calls the same reconciler for that user).
**Not building:** win-back campaigns, partial refunds.
**Acceptance:** time-travel test (Carbon::setTestNow): paid→lapse day 0 → codes
grace (scans still redirect w/ banner per M1-T6); day 15 → 3 newest active-free
with splash, others paused (410); renew day 20 → all active, splash off, within
one queue cycle. No state ever yields a 500 on scan.
**Review focus:** "3 newest stay alive" selection is deterministic and documented
(order by last_scanned_at desc NULLS LAST, then created_at desc — the codes that
are actually printed somewhere survive).

## M3-T4 — Plan gating sweep + pricing page — size M
**Scope:** apply Entitlements across every existing surface (create limit already;
add: styling lock, svg export, retention clamp, analytics_depth flag pass-through).
Pricing page (public, Bahasa): 4-tier table per TASKS.md numbers, annual toggle
default ON, custom-domain row labeled "segera hadir", Midtrans payment logos.
**Acceptance:** downgrade path — Plus user with 40 codes lapses to free → only
gated at *creation*, existing codes follow M3-T3 rules (never silently delete);
every gate returns the same shaped `{upgrade_to: "regular"}` payload.
**Review focus:** gate consistency — grep for hardcoded `'free'` string outside
config/plans.php; should be zero.

## M3-T5 — File/PDF QR type — size L
**Scope:** extend type enum usage: `file` destination `{disk_path, original_name,
mime, size, dl_url}`. Upload ≤ 10MB pdf/jpg/png to **Cloudflare R2** (S3 driver,
bucket `kodeqr-files`, key `files/{user_id}/{ulid}.{ext}`). Redirect for file
codes 302s to a public R2 URL (custom domain `files.kodeqr.com` proxied). Paid
plans only (PlanConfig `file_qr: bool`, free=false). Files inherit code lifecycle:
paused/blocked code → file link returns via app 410 (serve through signed
short-TTL URL so R2 isn't a bypass: dest_url = app route `/x/{slug}` → controller
issues R2 signed URL valid 5 min — keeps I1 mostly intact; note the extra hop is
paid-only traffic).
**Acceptance:** menu.pdf upload → scan on phone opens PDF inline < 2s; pause code
→ scan gets 410, previously-issued signed URL expires ≤ 5 min; 11MB upload → 422;
exe renamed .pdf → 422 (server-side mime sniff, not extension).
**Review focus:** the R2-bypass hole — signed URLs + short TTL is the mechanism;
confirm no permanent public URL is ever exposed in payloads or dashboards.

## M3-T6 — vCard hosted page — size M
**Scope:** type `vcard`, destination `{name, title, org, phone, wa, email, links[]}`.
/x redirect → hosted profile page (Blade, mobile-first, "Simpan Kontak" button
serving generated .vcf) — the page IS the destination, editable anytime.
**Acceptance:** .vcf imports on iOS + Android with correct fields incl. `62…`
phone; page LCP < 1.5s cellular.
**Review focus:** vCard 3.0 escaping (`;`, `,`, newline in fields).

## M3-T7 — Bahasa localization + frames — size M
**Scope:** `lang/id` full sweep (UI, emails, validation via laravel-lang + manual
pass on kodeqr strings), locale default `id`, `en` kept for the accidental
American. Print frames: 3 frame templates ("Scan untuk lihat menu", "Chat kami",
custom text) baked into export pipeline + A6/A4 print-PDF export preset (300dpi,
crop marks) — paid only.
**Acceptance:** zero English strings on the 6 core screens (manual sweep);
A6 PDF prints at a real print shop / home printer with crop marks aligned and
scans from the physical result.
**Review focus:** hardcoded strings in React components (they escape lang files
easily — grep for Indonesian-less JSX literals).
