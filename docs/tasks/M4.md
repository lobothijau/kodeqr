# M4 — B2B Tilt + Abuse Autonomy (Week 3)

Agencies and F&B chains are the likely first payers; this milestone is why Plus/
Business exist. Cut-list order applies here first when behind.

---

## M4-T1 — Folders + search — size S
**Scope:** `folders` table (user_id, name, color), nullable `folder_id` on
qr_codes, index filter pills + name search (LIKE, debounced).
**Acceptance:** moving codes between folders never touches slug/status/cache;
search 100 codes < 150ms.
**Review focus:** folder delete behavior — codes orphan to null, never cascade.

## M4-T2 — Multi-link landing page type (`linkpage`) — size L
**Scope:** destination `{title, bio, avatar_path, theme: enum(light,dark,brand),
links: [{label, url, icon: enum(wa,ig,tiktok,tokopedia,shopee,web,maps)}] max 10}`.
Hosted page mobile-first; every link click tracked as `link_click` — new table
`link_clicks` (qr_code_id, link_index, occurred_at, ip_hash) fed through the SAME
buffer/processor pattern as scans (extend payload with `kind`). Each link URL
passes Safe Browsing (M1-T5 client) on save.
**Acceptance:** page LCP < 1.5s cellular; per-link click counts on dashboard;
dirty URL in slot 3 → 422 names slot 3; 11th link → 422.
**Review focus:** click tracking re-uses the buffer invariants (I2/I3/I4) — no
new ad-hoc insert path.

## M4-T3 — Bulk CSV creation — size M
**Scope:** Plus/Business: CSV upload (`name,type,destination,folder`) max 500
rows/batch → validate ALL rows first, reject file listing row-numbered errors, on
clean: create + zip of PNGs emailed/downloadable. Counts against plan limit
atomically (all-or-nothing).
**Acceptance:** 500-row valid file → 500 codes + zip < 60s (queued); file with 1
bad row on line 400 → zero codes created, error names line 400; batch that would
exceed plan limit → rejected before creating any.
**Review focus:** all-or-nothing transactionality + the plan-limit race (lock).

## M4-T4 — Advanced analytics (Plus+) — size L
**Scope:** behind `analytics_depth=advanced`: hour×weekday heatmap (WIB), OS/
browser tables, compare-2-codes overlay chart, per-code CSV export (streams
scan_events minus ip_hash), UTM builder on destination edit (auto-append
utm_source=kodeqr&utm_medium=qr&utm_campaign={slug}, toggleable).
**Acceptance:** heatmap cell (Sen 12:00) matches hand-counted seeded events;
CSV of 50k events streams < 10s without memory spike (assert peak < 128MB);
Regular user hitting advanced endpoints → 403 upgrade payload.
**Review focus:** the heatmap timezone math (UTC→WIB shifting weekday at
midnight boundaries — seed events at 23:30 and 00:30 WIB and assert cells).

## M4-T5 — Weekly email report — size S
**Scope:** Monday 08:00 WIB queued mail per active paid user: 7d scans, top code,
top city, trend vs prior week. Unsubscribe flag on profile.
**Acceptance:** mailable snapshot test; user with zero scans gets the "belum ada
scan minggu ini" variant, not an empty template.
**Review focus:** query cost — one aggregate query per user, not per code.

## M4-T6 — Abuse autonomy — size M
**Scope:** nightly `abuse:rescan` — all active url/linkpage destinations through
Safe Browsing in chunks of 500 (API supports batch), hits → auto `blocked` +
owner email + admin digest. Creation rate limits: free 10 codes/day, paid
100/day (429 with Bahasa message). Minimal admin page (`/admin`, gate:
`is_admin`): abuse_flags list, one-click block/unblock, daily counts.
**Acceptance:** seeded dirty destination → blocked overnight run + both emails;
11th create today on free → 429; block button → abuse page live < 5s.
**Review focus:** rescan chunking respects Safe Browsing quota (10k URLs/request
limit and daily quota — batch endpoint, backoff on 429).
