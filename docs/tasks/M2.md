# M2 — QR Builder, Styling, Dashboard (Week 1b)

CRUD-heavy; tasks are terse on purpose. Inertia pages live in
`resources/js/Pages/Qr/`. Server renders canonical QR; client previews.

---

## M2-T1 — QR CRUD pages — size M
**Scope:** Index (list w/ status pill, scan_count, sparkline placeholder), Create
(type picker: URL | WhatsApp), Edit, soft Delete + Pause toggle. Gate
`create-qr-code` enforced server-side with upgrade-prompt error, limit shown in UI
("3 dari 3 kode terpakai"). Slug displayed, not editable.
**Not building:** styling (T2), folders (M4), file/vcard types.
**Acceptance:** 4th create on free → 403 with upgrade CTA, not a crash; pause →
scan shows 410 page ≤ 5s (observer cache-forget from M1-T1 fires on status change).
**Review focus:** authorization — every route policy-checked (`QrCodePolicy`),
IDOR test: user B requesting user A's code id → 403/404.

## M2-T2 — Server-side QR renderer — size M
**Scope:** `QrRenderer::render(QrCode $qr, RenderSpec $spec): string` using
`bacon/qr-code`. RenderSpec: `format` png|svg, `size` px (240–2048), `fg`/`bg` hex,
`logo` path nullable, `ecc` — force `H` when logo present else `M`. Logo composited
≤ 20% of area, white knockout pad. Encoded content is ALWAYS
`https://kodeqr.com/x/{slug}` — never the destination.
**Acceptance:** rendered PNG with logo scans from paper at 2cm² (manual, phone);
SVG opens in Inkscape with vector modules (not embedded raster); fg=#FFF bg=#FFF
rejected 422 ("kontras tidak cukup", luminance-diff check ≥ 40%).
**Review focus:** the encoded string. If anyone ever encodes destination instead of
/x URL, the entire dynamic premise is silently dead. Grep-level certainty.

## M2-T3 — Builder UI with live preview — size L
**Scope:** Create/Edit right-rail preview: client-side render (`qrcode` npm lib is
fine for preview parity), controls: fg/bg pickers w/ preset palette, logo upload
(≤1MB png/jpg/svg→rasterized, stored `logos/{user_id}/`), size select. Free plan:
pickers visible but locked with upgrade tooltip (`vector_export`/styling per
PlanConfig `analytics_depth`-style flags — add `styling: bool` to config).
**Not building:** frames/CTA labels (M3-T7), templates.
**Acceptance:** preview and server PNG visually match for same spec (snapshot test
on server side; eyeball parity manually); locked control never reaches server (and
server rejects anyway — assert both).
**Review focus:** client/server drift — two renderers, one source of truth for
defaults (share via props from PlanConfig, no hardcoded hex in React).

## M2-T4 — Export endpoints — size S
**Scope:** `GET /qr/{id}/export?format=png|svg&size=1024`. Free: png only, adds
frame caption "kodeqr.com" baked under code; paid: no caption, svg unlocked.
Content-Disposition attachment, filename `kodeqr-{slug}.{ext}`.
**Acceptance:** free svg request → 403 upgrade payload; caption absent on paid png;
2048px png < 400KB.
**Review focus:** caption is part of the image (canvas-composited), not HTML.

## M2-T5 — Per-code analytics dashboard (basic) — size L
**Scope:** `Qr/Show` page: KPI row (total, unique, last scan), scans-over-time chart
(day granularity, range picker 7/30/90d clamped to plan retention_days), top-5
cities bar, device split donut. Data endpoint `GET /qr/{id}/stats?range=30` returns
JSON aggregating **scan_events directly** (aggregates tables come alive in M5-T1 —
write the query behind a `StatsRepository` interface so M5 swaps implementation
without touching the page). All queries filter `is_bot = false`.
**Acceptance:** stats for a code with 10k seeded events < 300ms; free user
requesting range=30 gets data clamped to 7 days with a `clamped: true` flag the UI
renders as an upgrade banner; is_bot events invisible.
**Review focus:** timezone — group-by-day must bucket in Asia/Jakarta, not UTC
(`CONVERT_TZ` or compute date at insert—decision: add `local_date` DATE column in
M1-T4's insert? No — CONVERT_TZ here, note index implications in BACKLOG if slow).

## M2-T6 — Account dashboard home — size S
**Scope:** landing after login: codes-used meter, total scans 7d, recent codes
table, "Buat QR" CTA. Empty state that teaches (3-step illustration).
**Acceptance:** renders < 200ms with zero codes and with 100 codes.
**Review focus:** N+1 on the codes table (eager load, assert query count).
